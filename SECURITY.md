# Security

## Trust model

- **Hermes** is the user-facing, policy-carrying agent. **Pi** executes delegated
  work under the *user's own* permissions; the bridge adds no new privilege.
- The bridge stores only job metadata (task text, paths, ids, timestamps).
  It never writes secrets into job state, never reads API keys, and its logs are
  plain job-local text files under `$PI_BRIDGE_HOME` (protect them like your
  Pi/Hermes config).

## Wake channel (webhook)

- Binds `127.0.0.1` only (operator config); never set a public bind.
- HMAC-SHA256 **V2** scheme: `hex(HMAC(secret, "<timestamp>.<raw_body>"))` with
  the timestamp bound into the signature and a ±300 s freshness window
  (replay-protected), enforced per route. A missing/invalid signature is rejected.
- The secret lives in `~/.hermes/config.yaml` and `$PI_BRIDGE_HOME/wake.json`
  (mode 0600). It is never stored in job state, never returned by `pi_status`/
  `pi_list`, never logged by the runner.
- Idempotency: a constant `X-Request-ID` per (job, turn) is cached for one hour,
  so retries cannot start duplicate agent runs.
- The woken run treats `final_result_excerpt` as **untrusted data**, never as
  instructions (fixed in the route prompt template).
- Turning the channel off is instant (`enabled: false` in `wake.json`) and
  requires no restart; without it the bridge simply behaves like a job runner.

## Task execution

- No `shell=True`, anywhere. Task text is delivered to Pi on **stdin**; all
  subprocess calls use argv lists.
- `cwd` must exist and is normalized to an absolute real path before use.
- Job ids are generated by the bridge; user-supplied PIDs are never accepted;
  `pi_cancel` only stops units/runners recorded in bridge state.
- Returned results are length-bounded (stdout cap + excerpt caps) so a hostile
  or runaway job cannot flood the Hermes context.

## Optional PI WEB observability

- Read-only: `GET /api/...` and a single `POST /api/projects` registration of an
  existing working directory. It never edits PI WEB configuration, sessions or
  trust settings, and it degrades to "unavailable" on any error.
- Disable it (default) by leaving `PI_BRIDGE_PIWEB_URL` unset/unreachable — no
  behavior change.

## What the woken run can do

The Hermes webhook route grants toolsets (e.g. `pi_bridge`, `terminal`, `file`)
to the woken agent run — that is the deliberate, security-relevant decision.
Keep the route loopback-only, keep the secret strong
(`python3 -c "import secrets;print(secrets.token_urlsafe(32))"`), and scope
`toolsets` to the minimum your acceptance checks need.

## Reporting

Open a private issue / security contact of the deployment owner. Do not post
